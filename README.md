# 雲のたね

**▶ 作品を開く: https://shota-tdkr.github.io/weather-vapor-app/**

ブラウザで上の URL を開くだけで動きます。インストール・ログイン不要。

第7回学力向上アプリコンテスト応募作品。中学3年生の弟への聞き取りから
出発した、中学理科「天気とその変化」の中の**雲のでき方**にしぼった
学習アプリです。

---

## 一行で言うと

空気の塊を山で持ち上げると、冷えた空気が水蒸気を抱えきれなくなって
雲ができる — 中学理科「天気」の**凝結のしくみ**を、公式ではなく
「目で追う現象」として体験するアプリ。

## 何を学ぶアプリか

中学3年・理科「天気とその変化」の中の、

> **空気が上昇して冷える → その気温で抱えられる水蒸気量（飽和水蒸気量）が
> 下がる → 抱えきれなくなった分が水滴になって雲になる**

という一連の因果を対象にしています。

教科書は「西高東低だから日本海側は雪」のように、原因 → 結果の順で
覚えさせます。このアプリは逆に、**結果（雲ができる）を先に見せて、
原因（持ち上げる → 冷える → 抱えきれなくなる）を、手を動かして
見つけさせます。** 天気予報士ごっこではなく、天気の神様ごっこです。

核となる仮説: 生徒がつまずいているのは飽和水蒸気量の計算式ではなく、
「空気が冷えると水蒸気を抱えきれなくなる」という現象そのものが体感
として掴めていないこと。だから式ではなく、現象そのものを目で追わせる
設計にしています。

## 対象

- 中学3年生（理科「天気とその変化」を学習中、または復習）
- 中学理科の前提知識がない人でも入り口が分かるよう、初回起動時に
  「冷たいコップに水滴がつくのはなぜか」から入るチュートリアルを出します。

## 動かし方

1. https://shota-tdkr.github.io/weather-vapor-app/ をブラウザで開く。
2. 初回は使い方のガイド（吹き出し4ステップ）が出ます。「はじめる」を押すと

表示にスクロールが必要になります。

## 操作方法

### 距離レバー（マップの下・横向き）

右へ動かすほど、空気の塊（○）が山に近づきます。**山にぶつかるまでは
地面の上を流れてくるだけで高さは 0 のまま**で、斜面に入ってから斜面に
沿って自動で持ち上がります（教科書の地形性上昇と同じ順序）。
持ち上がると、

- 気温が下がる（左上の情報パネル）
- その気温で抱えられる水蒸気量（＝上限。ゲージの点線）が下がってくる
- 点線が「今持っている水蒸気の量」（ゲージの塗り）を下回った分が水滴に
  なり、○の上に雲が現れて、さらに上げると大きく育つ

### 水蒸気の量スライダー（距離レバーの直下・4段階）

空気の塊がはじめから持っている水蒸気の量を切り替えます。
少ない / やや少ない / やや多い / 多い の4段階（4.8 / 6.8 / 9.4 /
11.6 g/m³）。条件を変えると、雲のできる高さがどう変わるか比べてみましょう
（「水蒸気の量が多いほど低い高さで雲になる」ことは、お題モードのタイプ C で
自分で確かめる形にしてあり、画面の凡例には先に書いていません）。

### お題モード（「お題に挑戦」ボタン）

予想 → 確かめる → 答え合わせ、を1回3問。**タイプ C → B → A の順**で、3つの
問い方を1問ずつ出します（比較で法則を掴む → 条件判断で使う → 具体的な位置を
予測する、という流れ）。

- **タイプC**「A・B どちらが低い高さで雲になる？」— 水蒸気の量が違う
  2つの空気を比べる2択 → 「確かめる」を押すと A・B が順に自動で上がり、
  雲になった高さに水平線が2本残る（下にある線ほど低い高さで雲になった）。
- **タイプB**「高さ 65 / 100（やや高い）まで上げたら、雲はできる？」—
  「できる／まだできない」の2択 → 「確かめる」を押すと空気の塊が自動で
  その高さまで上がる。数字だけでは高い・低いが掴みにくいので、問題文に
  言葉のラベル（低い / やや低い / 中くらい / やや高い / 高い）を添え、
  さらにマップ上のその高さにも目印を1つ出します（○が止まる位置＝ゴール線）。
- **タイプA**「水蒸気の量が『やや多い』空気です。（9.4 g/m³）高さがどの
  くらいになると、雲ができるだろう？」— 4択で高さを予想 → 距離レバーを
  動かして確かめる。選択肢（10 / 25 / 50 / 75）が山のどのあたりに当たるか、
  マップ上に目印と数字が出ます。
- どのタイプも、出題した瞬間に○が画面の左端（遠方）から山のふもとへ
  すっと滑ってきます（「空気が山に流れてきた」導入。この間は高さ 0 の
  ままで、気温・ゲージ・雲は動きません）。
- 各問題の開始時に変化ログはいったん空になり、「予想を選んで、確かめて
  みよう」の案内だけが出ます（前の問題の「雲ができました」が残って、
  今の問題の結果と混ざらないようにするため）。

問題文は段階のラベル（多い / 少ない）を主に、g/m³ の数値をかっこ書きの
補助にしています。高さは「65 / 100」の相対値で、実際のメートルでは
ありません。

- **毎回、内容がランダムに変わります**（各タイプのプール = A 4通り / B 20通り /
  C 6通り から1問ずつ選び、さらにタイプ C は A・B の並びを 50% で入れ替えるので
  4×20×(6×2) = 960 通り）。もう一度挑戦しても同じ3問にはなりません。
- 「不正解」「間違い」といった否定的な言葉は使いません。予想が当たっても
  外れても、実際の答えと理由を淡々と見せます。
- 3問終わると「あなたの予想」と「実際」を**出題順に**並べた表が出ます。
  正解数は表示しませんが、見比べればどこがずれたか分かります。タイプ C を
  通じて「水蒸気の量が多い空気ほど、低い高さで雲になる」ことを体験します。

### 変化ログ（画面の下）

レバーを動かすたびに、因果を1段ずつ順番に表示します。

```
空気の塊を持ち上げました
→ まわりの気圧が下がり、空気がふくらみました
→ 気温が 15.0℃ から 1.1℃ に下がりました
→ 水蒸気の上限が 12.8 g/m³ から 5.2 g/m³ に下がりました
→ 上限を超えた分が水滴になり、雲ができました
```

## 教材としての狙い

- **結果を先に、原因を後に。** 雲ができる様子を先に見せ、なぜそうなるかを
  自分で操作して探させる。
- **式ではなく現象。** 飽和水蒸気量の数式を覚えさせるのではなく、
  「上限が下がってきて、今持っている量に追いつかれる」という動きを
  目で追わせる。
- **操作するたびに因果を言語化する。** 変化ログを1段ずつ出すことで、
  「持ち上げたから冷えた」「冷えたから上限が下がった」という順序を
  体感できるようにする。
- **予想 → 検証の形にする。** お題モードで「操作に失敗した」ではなく
  「予想が外れた」という体験にして、失敗への抵抗感を下げる。
- **前提知識がなくても入れる導入。** チュートリアルは、身近なコップの
  結露から「空気は冷えると水を抱えきれなくなる」という一文を、
  「飽和水蒸気量」という言葉を使わずに先に渡す。
- **用語は教科書に合わせる。** 「水蒸気の量」「飽和水蒸気量」など、
  テストの問題文と地続きになる言葉を使う。

## このアプリの「モデル」と、意図的に簡略化した点

**本アプリは、気象や大気の物理を厳密に再現するシミュレーションでは
ありません。** 中学理科で「凝結のしくみ」を理解するのに必要な要素だけに
絞り、それ以外はルールベースで単純化しています。物理的な厳密さよりも、
**教育的な正しさ（教科書の説明と矛盾しないこと）を優先しました。**

- **高さは 0〜100 の相対値。** 画面の「高さ 25 / 100」は実際のメートル
  ではありません（画面にもその旨を明記しています）。実単位を名乗ると、
  下記の簡略化した気温の下がり方と現実の値との食い違いが問題になるため、
  あえて単位を持たせていません。**「山のふもと」を 0、「山頂まで持ち
  上げた状態」を 100** としています（山にぶつかる前の、地面の上を流れて
  くる区間は高さ 0）。
- **気温の下がり方は、アプリ内の簡略ルール。** 「持ち上げた高さに比例して
  気温が一定の割合で下がる」という単純な直線関係で計算しています
  （係数はアプリ内部の値）。実際の気温減率は乾燥／湿潤や高度で変わり
  ますが、そこは扱いません。
- **気圧そのものの数値計算は行っていません。** モデル内部では高さから気温を
  直接計算していますが、学習上必要な因果関係として「上昇 → 周囲の気圧低下
  → 膨張 → 温度低下」を画面上で説明しています。
- **山への接近と上昇を単純化しています。** 距離レバーで山に近づけると、
  地形に沿って決まった軌道で持ち上がります。風速・空気塊の大きさ・
  斜面の角度などは扱いません。山は「なぜ持ち上げられるのか」を示す
  装置として置いています。
- **飽和水蒸気量は、教科書の対応表の値をそのまま使っています。**
  気温 0 / 5 / 10 / 15 / 20 / 25 / 30℃ に対する飽和水蒸気量
  （4.8 / 6.8 / 9.4 / 12.8 / 17.3 / 23.1 / 30.4 g/m³）を教科書の表から
  取り、その間は直線で補間しています。
- **空気の水蒸気の量は4段階に限定しています**（4.8 / 6.8 / 9.4 /
  11.6 g/m³）。連続的に変えられるようにすると「どの値でもだいたい同じ」
  に見えてしまうため、雲のできる高さがはっきり変わる4点に絞りました。
  いずれも教科書の表で確かめられる値です（11.6 だけは、表の 15℃ 欄
  12.8 をそのまま使うと出発点で既に湿度 100% になってしまうため、
  少し余裕を残した値にしています）。

これらはすべて、**中学理科の「凝結のしくみ」を掴むのに要らない要素を
削るための、意図的な設計**です。

## 使用技術・ファイル構成

- 素の HTML + CSS + JavaScript。フレームワーク不使用、依存ライブラリなし。
- 描画は SVG。DOM 要素として構成しているので、ブラウザの開発者ツールで
  中身をそのまま確認できます。
- ドラッグ操作は Pointer Events に統一（マウスとタッチが同じコードで動く）。
- ビルド不要。`index.html` を開けば動きます。
- ホスティングは GitHub Pages。

| ファイル | 内容 |
|---|---|
| `index.html` | 画面の骨組み（SVG のマップ、レバー、お題パネル、変化ログ、チュートリアル） |
| `style.css`  | 見た目とレイアウト（レスポンシブ対応を含む） |
| `script.js`  | モデルの計算、操作の処理、テキストの管理（表示文言は1箇所に集約） |
